WordWeave did not start from a plan to make an educational product. It started because one of Ben's kids needed help with English grades, and a game seemed more useful than another round of conventional practice.

The first playable version came together quickly in the browser. From there the work shifted toward making it feel like a game people could return to: fixing scoring and sharing, expanding the word lists, adding a leaderboard, tightening the visual presentation, and experimenting with another puzzle mode built around math.

That progression is a useful example of the Signal Foundry approach. The educational reason for making WordWeave is real, but it does not need to dominate the player's experience. The better target is a word game that is worth playing on its own and happens to exercise the same skills we wanted to practice in the first place.

By this point the project had moved beyond a family prototype into a released browser game. It is still one of the clearest examples of why we make things this way: start with a problem close to home, build the thing we wish existed, and find out whether it becomes something larger.
